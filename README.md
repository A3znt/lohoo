# ركن

تطبيق ويب عربي لإدارة طلبات المتجر من فيسبوك وإنستغرام. يحفظ الطلبات في Cloudflare D1، وينشئ الشحنات ويتابعها عبر درب السبيل، ويرسل رسائل الزبائن عبر رِسالة. واجهة الإدارة والمندوبات منفصلة، وتُحسب عمولة 15 د.ل عند وصول الطلب.

[افتح ركن](https://daftar-orders-personal.daftar-orders-a3z.workers.dev) من الهاتف ويمكن إضافته إلى الشاشة الرئيسية. بقي عنوان الاستضافة التقني الحالي كما هو حتى تستمر جلسات الدخول وإشعارات الهاتف في التطبيق المثبّت.

## سير الطلب

1. تجلب الواجهة المدن والمناطق والمنتجات والأصناف وباقات التوصيل من درب السبيل، ثم تعرض تكلفة الشحن المحسوبة من الشركة.
   يمكن إضافة حتى ثمانية منتجات في طلب واحد، مع اختيار صنف وقياس وكمية وسعر لكل منتج من مخزون درب السبيل. يعرض النموذج إجمالي المنتجات ورسوم التوصيل والإجمالي النهائي قبل التأكيد، ويرسل جميع المنتجات إلى الشحنة نفسها. الدفع المتاح حاليًا هو النقد عند الاستلام. تظهر ملاحظات المندوبة وسائق الشحن في ملاحظات الشحنة.
   يشمل حساب التوصيل بنود الخصم السالبة التي ترجعها درب السبيل؛ مثل رسم 30 د.ل وخصم 10 د.ل يساويان 20 د.ل. يظهر كل بند في تفصيل السعر، ويُرفض الإجمالي السالب أو غير الرقمي.
   يمكن إدخال رقم أساسي وحتى أربعة أرقام إضافية مختلفة للزبون؛ تُنشأ جهة اتصال لكل رقم وتُربط كلها بالشحنة، بينما تذهب رسائل رِسالة إلى الرقم الأساسي فقط. تظهر الأرقام في التفاصيل والبحث وتصدير CSV. يعرض ركن قياسات الصنف من مخزون درب السبيل، ويقبل وزنًا تقريبيًا اختياريًا بالكيلو يرسله في ملاحظات الشحنة. فحصنا بيانات منتجات وشحنات درب السبيل الحية ولم نجد فيها حقل وزن مستقلًا؛ لذلك لا يدخل الوزن اليدوي في حساب سعر التوصيل.
2. عند تأكيد الطلب، ينشئ الخادم جهة الاتصال والشحنة في درب السبيل، ويحفظ رقم التتبع وكود ركن واسم من أدخل الطلب في ملاحظات الشحنة. أكواد ركن الجديدة: `ZN001` للمدير، و`MO001` لمنى، و`SA001` لسجى؛ لكل مُدخِل تسلسل مستقل من ثلاث خانات. نقلنا الطلبات القديمة حسب وقت إنشائها، بما فيها المحذوفة، مع حفظ رقمها السابق داخليًا لمطابقة سجلات الرسائل. رقم تتبع درب السبيل لا يتغيّر، والرسائل المرسلة سابقًا لا تُعاد تلقائيًا.
3. يرسل قالب رِسالة المعتمد تأكيد الطلب، ثم قالب الطريق عند انتقال الشحنة إلى التوصيل. تظهر حالة الرسالتين في تفاصيل الطلب، ويمكن إعادة المحاولة يدويًا للفشل المؤكد فقط.
4. تزامن درب السبيل ينبه المدير، ومُدخِل الطلب، والمندوبة المسؤولة إن كانت مختلفة، بحالات التأجيل وتعذر التوصيل والإلغاء. يظهر كود الطلب والزبون والمدينة والمنطقة والسبب في التنبيه داخل ركن وعلى الهاتف عند تفعيل Web Push. يفتح الإشعار أحدث نسخة من الطلب لمراجعة السبب. المدير يتلقى أيضًا تنبيهات الطلبات الجديدة وملخص الصباح.
5. يستحق رصيد المندوبة بعد تسجيل التسليم لدى درب السبيل، ويصرفه المدير من سجل المحفظة.

لا تُنشأ طلبيات تجريبية أثناء تغيير الأكواد؛ الطلبات الجديدة التي يُدخلها الفريق تحصل على الكود التالي تلقائيًا. أسماء دخول المندوبات تبدأ بحرفين إنجليزيين مختلفين حتى تبقى الأكواد مميزة، ويُحجز `ZN` للمدير.

## إشعارات المدير

يسجّل ركن تنبيهًا للمدير فور تأكيد طلب جديد من المندوبة، باسمها ورقم الطلب وكود درب السبيل. ويتابع تغيّر حالة الشحنة في درب السبيل، وتعديلات الطلب، والحذف والاستعادة، والتحصيل وصرف العمولات. تظهر الإشعارات داخل ركن خلال 15 ثانية أثناء فتحه، وتصل إشعارات Web Push للهاتف حتى عند إغلاقه بعد تفعيلها من زر الجرس والسماح بها في المتصفح. تبقى الإشعارات خاصة بحساب مستلمها، ويمنع المعرّف الثابت تكرار تنبيه إنشاء الطلب عند إعادة المحاولة.

تظهر المدينة والمنطقة على بطاقة كل طلب. صندوق الإشعارات يقسم الرسائل الجديدة والمقروءة، ويتيح عرض غير المقروءة فقط أو تحديدها كلها كمقروءة. إذا تغيّر إسناد طلب بعد إدخاله، يظل مُدخِله قادرًا على فتحه ومراجعة سبب تحديث درب السبيل، بينما تبقى العمولة في محفظة المندوبة المسؤولة فقط.

يرسل الخادم Web Push بأولوية عالية للأحداث المهمة. من لوحة الجرس يمكن تشغيل اختبار مؤجل 15 ثانية وإغلاق التطبيق للتأكد من عمل إشعارات الخلفية فعليًا على الجهاز؛ قبول خدمة Push للإرسال لا يضمن ظهور الإشعار إذا منعته إعدادات المتصفح أو الهاتف. تعرض الواجهة حالة السماح بالمتصفح وتطلب إعادة التفعيل إذا غابت الصلاحية.

## الحذف والشحنة المفقودة

يفحص ركن الشحنة برقم التتبع، ثم بمعرّفها المخزن إن وجد. إذا كانت موجودة، يحذفها من درب السبيل ثم ينقل سجلها إلى المحذوفات. إذا أكدت الواجهتان غيابها، يمكن نقل السجل إلى المحذوفات مباشرة. عند فشل الاتصال أو عدم تطابق المرجع يتوقف الحذف ويحتفظ بالسجل. تميّز المزامنة الشحنات المفقودة بإجراء مطلوب وتوقف رسائلها التلقائية حتى لا تصل رسالة تأكيد لطلب لا شحنة له.

إذا عاد رِسالة للعمل بعد إضافة الرصيد، تستمر رسائل الطلبات الجديدة تلقائيًا. الطلبات القديمة ذات الرسائل الفاشلة تحتاج مراجعة شحناتها قبل أي إعادة إرسال.

## التشغيل والتحقق

```sh
npm install
npm test
npm run typecheck:webapp
npm run typecheck
npm run lint
npm run build:cloudflare
```

واجهة الويب وواجهة البرمجة تعملان على Cloudflare Worker مع D1. متغيرات الخادم: `APP_TOKEN`، `ADMIN_PASSWORD_SALT`، `ADMIN_PASSWORD_HASH`، `DARB_API_KEY`، `DARB_ACCOUNT_ID`، `RESALA_API_KEY`، `RESALA_CONFIRM_ADDRESS_TEMPLATE_ID`، و`RESALA_ON_WAY_TEMPLATE_ID`. تبقى المفاتيح في أسرار الخادم وملفات `.private/` و`.dev.vars` المستثناة من Git. قوالب الرسائل موثقة في [shared/confirmation.mjs](shared/confirmation.mjs)، وعميل رِسالة المستقل في [integrations/resala-client](integrations/resala-client/README.md).

كلمة مرور المدير المحلية في `.private/app-setup.txt`، وبيانات الفريق في `.private/team-credentials.json`. يمكن للمدير إدارة الحسابات وكلمات المرور من الواجهة.

عند تعديل الواجهة أو الخادم أو التكاملات، حدّث هذا الملف مع التغيير واختباره قبل اعتبار العمل مكتملًا. بناء المشروع لا ينشر النسخة تلقائيًا؛ النشر خطوة منفصلة.
